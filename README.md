# -cuda-performance-computing
This repository documents a self-directed learning project on the fundamentals of CUDA C++ , NVIDIA’s programming model for writing code that runs directly on the GPU. The project was completed as part of the Module 1 “Growing a Competency” assignment in CSE423 Capstone I at Arizona State University (Summer 2026), with prior approval from the instructor.

The motivation behind this project was career focused. I am interested in computer architecture, GPU programming, and AI hardware engineering; fields focused on parallel computing, accelerator design, and high-performance systems. Most undergraduate computer science and engineering students graduate with little to no hands-on GPU programming experience, so the goal of this project was to move from zero CUDA experience to compiling, benchmarking, and understanding real GPU kernels during a focused 8-hour learning sprint.

Three demos are included in this repository. hello.cu introduces the CUDA execution model, including kernels, threads, blocks, and the relationship between threadIdx, blockIdx, and blockDim. vectoradd.cu scales the same model to 1,048,576 elements added in parallel while introducing GPU memory management with cudaMalloc and cudaMemcpy. matmul.cu implements a 1024×1024 integer matrix multiplication on the GPU and compares its execution time against a single-threaded CPU implementation using CUDA event-based timing.

The programs were benchmarked on a free NVIDIA Tesla T4 GPU (16 GB, CUDA 12.x) using Google Colab and Kaggle Notebooks. The naive matrix multiplication kernel observed approximately an 845× speedup over the CPU implementation (CPU: 7.4 seconds, GPU: 0.009 seconds). The kernel intentionally avoids advanced optimizations such as shared-memory tiling or NVIDIA’s cuBLAS library in order to focus on the fundamentals of GPU execution and parallel computation.

The biggest takeaway from this project was realizing that the main challenge in GPU computing is often not raw compute power, but memory movement and data layout. Working directly with cudaMemcpy made the concept of the “memory bandwidth wall” much more concrete. It also helped connect classroom learning to real industry trends in AI hardware acceleration, where modern accelerators increasingly focus on reducing memory-transfer overhead and keeping data closer to compute resources. More importantly, this project gave me a practical foundation in CUDA and parallel computing that I can continue building on in future systems, architecture, and AI hardware work.
